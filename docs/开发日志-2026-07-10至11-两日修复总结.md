# 开发日志：2026-07-10 至 2026-07-11 两日修复总结

## 1. 总体说明

这两天的工作不是新增独立业务模块，而是对现有医务室系统做集中稳定性、数据一致性和发布安全加固。

- 7 月 10 日重点处理配置认证、库存流水、收费统计、备份恢复和前端工作流。
- 7 月 11 日重点处理业务时间统一、自动化测试门禁和历史 Alembic 迁移链。
- 保持医生、护士、管理员、财务四角色和既有处方状态机兼容，没有合并其他分支中的实验功能。

## 2. 7 月 10 日：主线稳定性与安全修复

### 2.1 配置、认证与接口安全

- 默认数据库位置统一为项目根目录 `data/app.db`，并保留通过环境变量连接 MySQL 的能力。
- 未配置密钥时生成并持久化强随机运行时密钥，多进程首次启动使用系统锁避免生成不一致密钥。
- 基础账号不再使用公开固定密码，改为 `BOOTSTRAP_PASSWORD` 或启动时生成的随机临时密码。
- 创建账号、重置密码和自助改密统一执行至少 12 位密码策略。
- 使用 `token_version` 让改密、重置和停用前签发的 JWT 立即失效。
- 管理员删除账号改为软停用，可重新启用，并保留历史接诊、收费、库存和审计归属。
- 默认只监听 `127.0.0.1`；CORS、请求体大小和 Excel 解压行列数均增加限制。
- 修复病例打印存储型 XSS、财务患者隐私泄露和 Excel 公式注入风险。
- API 404 与全局错误统一返回安全 JSON，不再向客户端暴露内部异常文本。

### 2.2 数据库兼容

- `_sync_model_schema()` 以当前 ORM 为来源，幂等补齐缺失表、可空字段和非唯一索引。
- 运行时同步只增加结构，不删除历史字段；改型、非空、唯一约束和外键仍必须使用 Alembic。
- SQLite 统一启用外键检查和写锁等待。
- 患者拼音字段改为有界字符串，兼容 MySQL 索引限制。
- SQLite 到 MySQL 数据迁移使用单一源快照、模型表原子替换和提交前外键孤儿检查。
- 迁移和字符集转换仅处理 ORM 模型表，不删除扩展表、运维表或 `alembic_version`。

### 2.3 库存、盘点和月报

- `InventoryRecord` 增加 `visit_id` 和结构化 `operation_type`。
- 处方执行写入 `dispense` 出库流水，撤销写入 `reversal` 返库流水。
- 对旧版已撤销交易幂等补记历史执行与撤销流水。
- 月报按结构化流水计算，跨日撤销分别归属执行日和撤销日。
- 整装和零售库存组统一换算为最小基础单位，保证库存守恒。
- 每日快照只允许零点调度创建，白天重启不再生成错误期初库存。
- 联合盘点修复零售变体库存放大问题，并增加整数范围校验。
- 智能盘库改为“扫描候选、人工核对、确认合并”，执行前再次校验候选未变化。
- CSV 导入增加类型、批次、效期、有限数和负库存检查。

### 2.4 收费、营收和备份

- 支付方式、优惠标记和金额增加严格校验，金额按两位小数规则处理。
- 职工优惠仅允许用于教职工患者，分项实收不能超过应收金额。
- 新增统一收入分摊服务，确保诊查、药品、诊疗项目和耗材之和等于实际收费。
- 管理统计、Excel 导出和财务看板统一收入口径及北京时间查询边界。
- SQLite 备份改用在线 Backup API，避免直接复制正在写入的数据库和 WAL。
- MySQL 备份使用 `mysqldump --single-transaction`，临时文件在响应后清理。

### 2.5 前端工作流

- 医生、护士、财务端增加账号设置入口。
- Axios 统一处理登录失效，同时保留普通业务校验错误。
- 处方执行使用受控二次确认。
- 智能盘库展示完整候选并要求逐项确认。
- 月报导出检查状态码、鉴权、响应类型和空文件，不再下载伪 Excel 错误文件。

## 3. 7 月 11 日：时间、测试门禁与 Alembic 收口

### 3.1 业务时间统一

- 建立统一 UTC 与 `Asia/Shanghai` 转换工具。
- 数据库存储继续兼容 naive UTC，API 输入按北京时间转换，页面和导出固定显示北京时间。
- 管理、医生和护士接口中散落的手工 `+8/-8` 被公共工具替代。
- 历史记录、运营日志和入库时间筛选统一为 UTC 半开区间。
- 修复首日凌晨、次日零点、结束日微秒记录和 XLSX 时间标签问题。

### 3.2 测试和发布门禁

- `run_backend_tests.py` 改为自动发现 `backend/tests/test_*.py` 全部测试。
- Linux Release 固定兼容 Vite 8 的 Node.js 版本。
- 发布工作流增加后端全量测试和 Python `compileall`。
- 中英文 README 和后端开发说明同步更新运行要求与测试命令。

### 3.3 历史 Alembic 迁移链

- 历史 revision 改为幂等接管已有表、列、索引和约束，不再删除核心业务表。
- 新增共享迁移 helper，检查同名对象冲突、前缀/特殊索引、唯一约束和外键语义。
- 首个 revision 仅允许接管精确匹配且无数据的部分初始化空表，拒绝非空或混有未知表的残缺结构。
- 历史链到 `b6e1d8f3a2c4` 明确为 forward-only，所有危险 downgrade 统一拒绝。
- 迁移依赖在线结构和数据检查，因此离线 `--sql` 生成明确拒绝。
- SQLite 迁移使用显式外层事务，失败时整体回滚并恢复 `PRAGMA foreign_keys=ON`。
- 迁移前已有外键悬空记录可以原样保留，但迁移产生新的悬空记录会导致整体失败。
- 旧 `inventory_record` 会补齐 `visit_id`、`operation_type`、索引和外键。
- 已知短字符串只扩展不缩短，拼音 TEXT 转换前检查实际数据长度并保留注释、默认值和排序规则。

### 3.4 `ture.db` 真实旧库副本验收

- 原数据库始终只读，只使用临时副本执行升级。
- 副本从 `bbf28ffdb4c0` 成功升级到 `b6e1d8f3a2c4`。
- 13 张业务表共 105,122 行，逐表行数和全部主键升级前后一致。
- 22 个 ORM 外历史扩展字段及其值完整保留。
- 迁移前已有的 1,227 条外键悬空记录关系和数量保持不变。
- 原文件 SHA-256 保持为 `57A015AE783F1BDB51A6F1B1B9A51EC0B46FC88C635956CA7316049ED8383A9C`。

### 3.5 MySQL 隔离验收器

- 新增 `scripts/validate_mysql_alembic.py`。
- 覆盖空库升级、运行时超前历史结构接管和非事务 DDL 中断重试。
- 管理员凭据只通过本机 `mysql_config_editor` login-path 读取。
- 仅允许 `127.0.0.1` 上的 MySQL 8.0.21+，拒绝 MariaDB、远程明文连接和默认 binlog 风险。
- 临时账号属性绑定 run ID、server UUID 和精确数据库名单。
- 所有管理 SQL 在同一连接中校验 server UUID，清理只删除所有权仍匹配的资源。
- 清理数据库失败时继续处理其他数据库，并锁定、保留所有权账号供后续处置。
