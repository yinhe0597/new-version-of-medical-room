# 开发日志：MySQL 生产发布加固（2026-07-13）

## 1. 目标与结论

本轮把数据库能力从“启动时可以读取 MySQL URL”推进为“具备受保护的预检、schema 升级、SQLite 数据搬迁、成品门禁和运行监控”。

当前代码仍只支持启动时选择一个 SQLite 或 MySQL 数据库，不支持热切换、双写、CDC 或自动回落。推荐发布边界是：在维护窗口内一次性迁移到 MySQL，此后 MySQL 成为唯一数据源。

## 2. 已完成

### 2.1 配置与启动防护

- `DATABASE_URL` 与 `SQLALCHEMY_DATABASE_URI` 同时指向不同目标时直接拒绝启动。
- 远程 MySQL 在连接前要求 CA、证书验证和主机名验证；本机回环或授权隧道可显式使用本地连接策略。
- 增加连接、读写、深度查询超时和连接池参数。
- MySQL URL query 使用严格 allowlist，仅接受 `charset`、`unix_socket` 和文档化的 `ssl_*` 项；目标、凭据、超时、连接时 SQL 和未知项在连接前被拒绝。允许项会转入直接 PyMySQL 参数，并在 engine 初始化前清除全部用户 query；框架仅可能补回固定的 `charset=utf8mb4`。运行时和迁移工厂也拒绝 `connect_args` 覆盖目标及 socket 双来源不一致。
- 所有 MySQL 强制关闭运行时 schema 同步、开启预检并要求唯一 Alembic head，危险显式覆盖不能作为逃生开关。
- 配置/schema/权限等永久 blocking 立即退出；临时连接和超时故障执行有限重试。

### 2.2 只读生产预检

新增 `scripts/check_production_database.py`，所有显式 SQL 受只读前缀限制，SQLite 使用 `mode=ro`。检查范围包括：

- 数据库类型、驱动、目标脱敏和迁移资源完整性。
- MySQL 8.0.21+、MariaDB 排除、TLS、utf8mb4、strict mode、InnoDB、时区和只读状态。
- Alembic head、模型表/列/类型/索引/唯一约束/外键。
- 运行账号最小 DML 权限；全局 `*.*` 除 `USAGE` 外为 blocking，角色授权和无法解析的授权按失败关闭处理，迁移账号使用独立策略。
- 全部模型外键的悬空记录。

CLI 支持人类可读和 JSON 报告，以 `0/1/2` 分别表示通过、警告、阻断。启动默认使用有界 profile，完整 CLI 检查为外键扫描注入查询时限。

### 2.3 数据迁移防护

- `backend/migrate_to_mysql.py` 统一使用 `DATABASE_URL`，仅兼容匹配的旧 `MYSQL_*` 配置，发现冲突即拒绝。
- 默认仅 dry-run；执行必须提供 `--execute --yes --expected-source-sha256`。
- 使用 SQLite 在线备份快照和 `quick_check`，dry-run 后源文件变化会导致执行拒绝。
- 目标必须位于唯一 Alembic head；清表前再次核对目标版本和数据状态。
- 源/目标字段必须完整对齐，任何无法保留的扩展字段或外键孤儿都会阻断；模型表与非模型扩展表存在任意方向交叉外键时拒绝全量替换。
- 复制前两次核对 strict mode、autocommit/只读状态和全部模型表 InnoDB；按 1000 行分批处理，在单个 MySQL DML 事务中逆序清表、复制，并在提交前核对逐表行数、全部主键摘要和数据库中的全部实际外键。

### 2.4 打包与运维入口

- Windows/Linux spec 加入 PyMySQL、MySQL dialect、生产 CLI、数据搬迁器和完整 Alembic 资源。
- 打包程序新增：
  - `--check-database`
  - `--migrate-database --backup-file <backup.zip> --yes`
  - `--import-sqlite <path>` 及受保护执行参数
- 新增 `/api/health/live` 和 `/api/health/ready`；MySQL readiness 持续检查 database、只读状态、strict mode、Alembic head 和运行账号授权漂移，失败返回 503，并对日志告警做节流。
- MySQL dump 增加一致性、流式、二进制、GTID/表空间兼容参数、Unix socket 支持和 v2 manifest；SQL 与 manifest 原子封装为 ZIP，前端重算收到的 ZIP 真实字节摘要后只触发一次下载。迁移门禁要求备份处于默认 60 分钟时效内，并在 DDL 前复核 `server_uuid`、Alembic head 和查询成功后得到的 GTID 状态；GTID 查询错误直接阻断，只有成功返回空值才按未启用处理。
- AppImage 使用镜像旁 `.env`，只读目录下把数据与日志回退到 XDG 可写目录；Linux 启动脚本等待 readiness 而非固定休眠。
- Linux 启动脚本将 200/503 等 HTTP 响应都视为端口已占用，以启动时刻和随机环境令牌校验 PID 身份，并用 `flock` 串行化启停；缺少 `flock` 时失败关闭，身份不匹配时不会向该 PID 发送信号。生产入口缺少 Waitress 或连续崩溃重试耗尽时返回非零退出码。

### 2.5 CI 门禁

- 保留后端全量测试、Python compileall、前端 `npm ci && npm run build` 和 PyInstaller 构建。
- 新增 MySQL 8 服务 job：Alembic 空库升级、运行账号降权、生产预检和 readiness 冒烟。
- MySQL 8 服务 job 自动执行 `fresh/history/retry` 三类 Alembic 场景，包括中断 DDL 后重试。
- CI 从 MySQL `USER()` 获取 service container 实际看到的客户端地址，只为该精确来源创建临时账号；显式安装 MySQL 8 客户端，并在任意结果下清除 login-path。
- Linux 单文件构建后使用真实 dump+manifest 执行成品 `--migrate-database`，再以降权运行账号执行 `--check-database`。
- 生成后的 AppImage 在只读镜像目录下执行 `--help` 和 MySQL `--check-database`，并验证未向镜像旁写入数据。
- 成品归档检查 PyMySQL、MySQL dialect、生产 CLI、迁移器和所有迁移资源。
