## 2. 已完成的迁移修复

- 历史 revision 改为幂等补表、补列、补索引和补约束，不再在 upgrade 中删除核心表。
- 新增共享迁移 helper，先检查同名对象冲突，再判断索引、唯一约束和外键语义是否等价。
- partial/prefix unique index、特殊索引选项、跨 schema 外键和非默认级联动作不再被误认为当前模型约束。
- 首个 revision 仅允许精确匹配且无数据的部分初始化空表续跑；先删除半成品空表，再按标准结构重建。任何非空或混有未知表的残缺库仍拒绝接管。
- SQLite 迁移在关闭外键后使用显式外层事务，所有 revision、版本戳更新和最终外键增量检查原子提交；失败会整体回滚并恢复 `PRAGMA foreign_keys=ON`。
- SQLite 允许保留迁移前已有的外键悬空记录，但拒绝迁移新增悬空记录。
- `inventory_record` 旧表会补齐 `visit_id` 和 `operation_type`，再补索引及外键。
- 字符串改型只扩展已知的短 VARCHAR；拼音 TEXT 转 VARCHAR 前检查最大数据长度，并保留默认值、注释、字符集和排序规则。不会缩短更宽字段。
- 历史链到 `b6e1d8f3a2c4` 明确为 forward-only。由于 revision 可能接管迁移前已存在的结构，`downgrade` 统一拒绝；回退必须恢复迁移前已验证备份。
- 依赖在线结构和数据检查，Alembic `--sql` 离线生成明确拒绝。执行迁移时必须停止应用实例，并确保只有一个在线迁移进程。
- 新增 `scripts/validate_mysql_alembic.py`，用随机隔离库覆盖 MySQL 空库升级、`bbf28ffdb4c0` 运行时超前结构接管，以及首个 revision 非事务 DDL 中断后的半成品重试。
- MySQL 历史夹具按 `ture.db` 对齐 22 个 ORM 外字段、9 个旧 server default、短 `password_hash`、TEXT 拼音列、缺失的用户状态列和旧 `inventory_record`，并校验所有主键、关键业务值、字段注释和二次升级幂等性。
- 验收器只允许 `127.0.0.1` 上的 MySQL 8.0.21+；管理员认证只读取 `mysql_config_editor` login-path。临时密码仅经 mysql stdin 传递，普通 option file、`MYSQL_*` 环境变量、自动重连和 `--force` 均被禁用。
- 临时账号先写入 run ID、server UUID 和精确数据库名单，再创建场景库；所有读取和写入均在实际 SQL 会话中校验 server UUID。清理失败时继续处理其他库，并保留、锁定所有权账号，避免误删或失去后续清理依据。

## 5. MySQL 8.0.26 实机验收（2026-07-12 已完成）

- 只读 probe 核对了服务器 UUID、版本、主机、端口、InnoDB、utf8mb4、严格模式及日志配置。
- 服务器启用了 binlog；本次明确使用 `--allow-binlog`，临时 DDL 和账号元数据会保留在本机 binlog 历史中。
- 首次实跑发现验收器夹具中的 `usage` 保留列未转义，以及 JSON 字面量 `:1` 被 SQLAlchemy 误解析为绑定参数；两处均已修复并增加回归测试。
- 隔离空库升级 `fresh`、历史结构接管 `history`、非事务 DDL 中断恢复 `retry` 全部通过。
- 验收结束后查询 `information_schema.SCHEMATA` 和 `mysql.user`，未发现任何残留的 `medroom_mig_*` 数据库或 `medmig_*` 账号。
- 未读取、修改或删除既有业务数据库。当前自动化终端无法响应 `mysql_config_editor` 的交互式密码提示，本次通过父进程一次性环境变量适配；密码未写入仓库、验收输出或 MySQL 子进程参数，临时适配器已删除。正式验证器仍只接受 login-path。

标准复验流程仍使用本机 login-path：

```powershell
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql_config_editor.exe' set `
  --login-path=codex-medroom --host=127.0.0.1 --port=3306 --user=root --password
```

- 配置后先只读探测并人工核对 UUID、版本、主机、端口和 binlog，再把完全相同的 UUID 传给完整验收：

```powershell
& backend\.venv\Scripts\python.exe scripts\validate_mysql_alembic.py `
  --login-path=codex-medroom --probe

& backend\.venv\Scripts\python.exe scripts\validate_mysql_alembic.py `
  --login-path=codex-medroom --expected-server-uuid=<uuid-from-probe>
```

若 probe 显示 `binlog=1`，脚本默认拒绝继续；只有明确接受临时 DDL 和账号元数据写入 binlog 后才可增加 `--allow-binlog`。

本轮 Alembic 迁移链的真实 MySQL 发布门禁现已满足。生产升级仍需遵循单迁移进程、停机维护、升级前备份和升级后结构对账流程。
