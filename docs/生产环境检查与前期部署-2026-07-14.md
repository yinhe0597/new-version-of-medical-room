## 8. SQLite 前期部署

1. 停止现有应用写入，复制数据库和 `data/.runtime-secrets.json` 到受控备份目录。
2. 只对数据库副本执行迁移：

```powershell
$source = Join-Path $env:USERPROFILE 'Desktop\ture.db'
$candidate = 'D:\medical-room-predeploy\data\app.db'
Copy-Item -LiteralPath $source -Destination $candidate
$env:DATABASE_URL = 'sqlite:///' + ($candidate -replace '\\', '/')
& backend\.venv\Scripts\python.exe -m flask `
  --app backend.migration_app:create_app `
  db -d backend/migrations upgrade
& backend\.venv\Scripts\python.exe scripts\check_production_database.py
```

3. `ture.db` 的 1,227 条历史孤儿不能静默带入正式库；必须经业务负责人确认保留策略。本文生成的置空副本只用于本机验证。
4. 将 `.env.production.example` 复制为 EXE 同目录下的 `.env`，保持 `SERVER_HOST=127.0.0.1`，通过 HTTPS 反向代理开放访问。
5. 把最终批准的数据库副本放到 EXE 同目录的 `data/app.db`。
6. 运行 `医务室管理系统.exe --check-database`：退出码 2 表示阻断，禁止启动；退出码 1 必须人工确认全部 warning。
7. 启动后验证 live/ready、登录、建档、开方、审核、执行、撤销、入库、报表和备份。
8. 完成业务对账和恢复演练后，才允许切换正式流量。

本机示例目录位于 `build/production-readiness/ture-example-package`，仅用于验证，不是可分发安装包。

## 9. MySQL 前期部署

1. 在隔离 MySQL 8.0.21+ 实例创建迁移账号和最小权限运行账号。
2. 将 `.env.production.example` 复制为 `.env`，配置 `DATABASE_URL`、CA 和 `MYSQLDUMP_PATH`，不要把凭据写入命令行或版本库。
3. 使用运行账号执行 `医务室管理系统.exe --check-database --json`。
4. 使用迁移账号和已校验的最新备份 ZIP 执行 schema 升级。
5. 对 SQLite 源先执行 `--import-sqlite <path>` dry-run，处理全部扩展字段和外键孤儿后再执行导入。
6. 切回运行账号，重新执行完整预检和核心业务冒烟。

任何 blocking、备份摘要不匹配、实例 UUID/GTID 变化或权限超限都必须停止发布。
