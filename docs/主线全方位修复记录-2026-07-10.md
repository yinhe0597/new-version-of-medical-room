# main 主线全方位修复记录（2026-07-10）

## 1. 修复基线

- 基线分支：`main`
- 基线提交：`386d8e3`
- 目标：处理《二次开发项目分析》中已经通过源码、Git 历史和测试确认的问题。
- 原则：保持现有四角色和处方状态机兼容，不整体合并 `dev` 或 `new_data`。

## 2. 配置与安全

- 删除 `backend/run.py` 的 D 盘数据库硬编码。
- 源码开发、初始化脚本和生产打包统一默认使用 `data/app.db`。
- `run_prod.py` 不再覆盖 `DATABASE_URL`/`SQLALCHEMY_DATABASE_URI`。
- 所有入口未配置密钥时，在 `data/.runtime-secrets.json` 生成并持久化强随机密钥；Windows 使用系统命名互斥量、Linux 使用文件锁，保证多进程首次启动得到同一组密钥。
- 所有启动入口统一使用 `BOOTSTRAP_PASSWORD` 或随机临时密码；旧库中的 `123456` 基础账号自动旋转。
- GitHub Linux Release 说明移除固定初始密码，改为说明 `BOOTSTRAP_PASSWORD` 或启动日志中的随机临时密码。
- 创建、重置、自助改密统一至少 12 位；通过 `token_version` 使改密前 JWT 立即失效。
- 账号“删除”改为软停用，保留接诊、收费、盘点和操作日志中的人员归属；停用会立即注销旧 JWT，并支持管理员重新启用。
- 默认仅监听 loopback；局域网监听必须显式配置，并要求 HTTPS 反向代理。
- 修复病例复盘打印中的患者姓名存储型 XSS。
- 财务报表保留业务功能，但后端强制脱敏姓名并移除学号、诊断、主诉。
- 未知 `/api/*` 返回 JSON 404；全局请求体限制为 12MB，Excel 增加解压体积及行列上限。
- 全局异常响应不再向客户端返回内部异常文本。
- CORS 改为 `CORS_ORIGINS` 允许列表，默认仅开放本地 Vite 地址。
- MySQL 初始化脚本移除共享明文密码；迁移工具强制从环境读取 `MYSQL_PASSWORD`。
- Git 历史中曾出现的旧 MySQL 凭据必须在所有已部署环境轮换/删除；公开分发前评估历史重写。
- 新增 `.env.example`，并忽略 `.venv/`、`data/` 和运行时密钥。

## 3. 数据库兼容

- 用 `_sync_model_schema()` 替换仅支持 SQLite 的手工补列清单。
- 当前 ORM 模型成为运行时兼容同步的唯一字段来源。
- SQLite/MySQL 均可幂等创建缺失表、补齐可空字段和非唯一索引。
- 同步只增加结构，不删除旧列；非空列、改型和复杂约束必须使用 Alembic。
- 停止在 main 新建未实现的 23 个中医相关“幽灵字段”。
- 患者类型历史回填改为事务提交，并同时支持 SQLite/MySQL。
- SQLite 统一开启外键约束和 15 秒写锁等待。
- 患者拼音索引字段改为有界字符串，避免 MySQL TEXT 索引失败。
- MySQL 迁移改为单一 SQLite 读快照、目标全表原子替换，并在提交前校验外键孤儿。
- MySQL 目标清理范围限制为当前 ORM 模型表，不删除扩展表、运维表或 `alembic_version`。
- 迁移专用配置关闭 APScheduler 和启动数据回填；字符集转换也限制为 ORM 模型表，避免后台任务或维护操作触碰同库扩展表。
- 旧 MySQL 受控升级 `user.password_hash` 到 `VARCHAR(256)`，并将患者拼音 `TEXT` 转为 `VARCHAR(255)` 后再创建索引。
- 药品列表和月报排序改为 `CASE WHEN ... IS NULL` 通用表达式，不再生成 MySQL 不支持的 `NULLS LAST`。

## 4. 库存一致性

- 新增进程内串行锁；MySQL 使用独立连接 advisory lock，覆盖所有库存和 Visit 写操作。
- 处方执行和撤销按固定顺序锁定 Visit、Drug、DrugStockGroup；MySQL 使用 `FOR UPDATE`。
- 执行前再次校验药品关联、数量、库存组和最小单位换算。
- 撤销遇到库存组丢失或换算无效时整体回滚，不再静默跳过库存返还。
- 库存调整、入库、药品价格和拆零参数增加非负、类型和范围校验。
- 诊疗项目禁止走库存补货接口，库存组物资禁止走旧补货接口。
- 库存流水新增结构化 `operation_type`，入库、盘点调整和智能合并不再依赖自由备注分类；旧数据保留已知系统备注兼容识别。
- `InventoryRecord` 增加 `visit_id`；处方执行写 `dispense` 出库流水，撤销写 `reversal` 返库流水。
- 老交易首次撤销时补记原出库；启动时对旧版已撤销交易幂等补记成对流水，并优先使用 `nurse_execute` 审计日志的真实执行时间和经手人。
- 月报优先读取执行/撤销流水，跨日撤销分别归属执行日和撤销日，不再抹掉历史出库。
- 整散库存组月报改为按最小基础单位输出单行，整装出库、零售出库跨整装边界均满足 `期初 + 入库 + 调整 - 出库 = 期末`。
- 月报查询改为北京时间半开区间，历史期末读取截止日次日零点快照；停用药品仍保留在历史报表中。
- 每日库存快照只允许北京时间零点调度创建，并在取得库存写锁后落库；服务白天重启不再把日中库存误记为当日期初。
- 零点快照遇库存锁忙或临时数据库异常会持续重试；延迟生成的快照结合 `created_at` 和期间流水归一化到北京时间零点边界。
- 联合盘点接口和页面统一使用库存组总量、整装换算量和零售份数，修复从零售变体打开盘点时可能成倍放大库存的问题。
- 联合盘点增加数据库整数上限校验，超限结果在写库前拒绝。
- CSV 导入按类型、批次、效期匹配，排除库存组，逐行保存点隔离且拒绝负数/非有限数。
- 患者批量导入和业务审计日志改为单事务，不再出现失败行部分更新。
- 护士入库新增购进价，追加/修改耗材同步采购成本。

## 5. 智能盘库

- 从“点击即自动合并删除”改为“扫描候选 -> 用户二次确认 -> 执行合并”。
- 库存组记录永不进入自动合并候选。
- 仅当类型、名称、规格、单位、批次、效期、价格、换算、库位、状态、入库时间全部一致时才列为候选。
- 合并时同步迁移 PrescriptionItem、InventoryRecord、DailyStockSnapshot。
- 同日库存快照合并求和，避免唯一键冲突。
- 合并产生库存流水和 OperationLog，可追溯操作人、候选和删除数量。
- 确认请求绑定首次预览的记录 ID；候选变化返回 409，不会合并未预览的新记录。
- 合并流水使用零差额审计记录，避免月报重复计算迁移库存。
- 阈值参数增加格式和范围校验。
- 前端逐组展示全部候选及记录明细，要求逐项勾选核对，全部完成后才开放合并操作。

## 6. 收费与财务

- 支付方式限制为现金、一卡通、其他。
- 优惠标记必须为布尔值；金额必须有限、非负并按 `ROUND_HALF_UP` 归一为两位小数。
- 分项实收必须成对提交，不能与旧版实收总额同时提交。
- 实收诊查费和实收物资/项目金额不能高于各自应收。
- 职工优惠只允许 `patient_type=staff`，教职工处方默认勾选优惠。
- 前端“实收药价”改为“实收物资及项目”，不再遗漏诊疗项目和耗材。
- 新增统一收入分摊服务：
  - 总收入始终以 `Payment.amount` 实收为准。
  - 分项优惠优先使用实收诊查费和实收物资/项目金额。
  - 物资/项目实收按原应收比例分配到药品、诊疗项目、耗材。
  - 旧优惠记录按全部原应收比例分摊。
  - 分位差额自动归集，四类收入之和严格等于总实收。
- 管理员统计、Excel 导出和财务收入占比统一使用同一口径。
- 财务收入占比移除 Visit N+1 查询。
- 医生诊查费、护士改价和执行结算统一拒绝负数、NaN、Infinity。
- 审核、驳回、改价、增删项目、执行、撤销按同一 Visit 锁序串行，关闭状态竞争窗口。
- 统计和导出统一按北京时间转换为 UTC 查询边界，修复凌晨收费归错日期。
- 医生、护士接口返回的业务时间固定按北京时间格式化，不依赖服务器系统时区。
- 财务姓名脱敏覆盖单字姓名；月报 XLSX 文本字段增加公式注入防护。
- 处方变更后前端自动重算职工优惠分项，避免少收或后端拒绝。

## 7. 备份

- `GET /api/admin/backup` 根据当前数据库直接下载 `.db` 或 `.sql`。
- 保留 `POST /api/admin/backup` 作为旧版 SQLite 服务端备份兼容接口。
- SQLite 改用在线 Backup API，避免直接复制正在写入的数据库/WAL 导致不一致。
- MySQL 使用 `mysqldump --single-transaction`，密码通过子进程环境变量传递，不出现在命令行。
- MySQL 导出改用临时文件并设置 300 秒超时；下载结束自动删除。
- SQLite GET 下载使用临时在线备份并自动删除；POST 保留备份最多 20 份。
- MySQL 备份错误详情只写服务日志，不返回客户端。
- 管理端根据响应类型生成正确扩展名。

## 8. 前端工作流

- 医生、护士、财务端增加账号设置路由和入口，复用真实改密接口。
- Axios 对 401 和 JWT 失效类 422 统一清理会话并返回登录页，同时保留普通业务 422 的原错误提示。
- 月报文件下载统一使用 Axios Blob，并检查鉴权失败、HTTP 状态、响应类型和空 Blob，避免把 JSON 错误响应保存为 Excel。
- 处方执行使用 Element Plus 二次确认；库存页恢复入库入口并修正移动端表单栅格。
- 管理端隐藏后端不支持的库存组操作，零售变体编辑不再错误提交购进价。

## 9. 规则与技术债

- 普通药品规则统一为：用法、用量、频次、时间至少填写一项。
- 清理主代码中的 SQLAlchemy `Query.get()` 旧 API。
- 时间默认值统一使用兼容现有字段的 naive UTC 辅助函数，消除 Python 3.12 `utcnow()` 弃用问题。
- 调度器初始化和挂单清理失败会记录异常，不再完全静默。

## 11. 仍需独立立项

- 金额字段从 Float 迁移为数据库 Numeric/Decimal，需要真实数据库迁移和前后端兼容方案。
- MySQL 结构同步、advisory lock、行锁、SQLite 到 MySQL 真实迁移和 `mysqldump` 需要连接真实 MySQL 环境做集成验收。
- Git 历史中出现过的旧 MySQL 凭据必须由部署方轮换或删除；是否重写公开仓库历史需要单独决策。
- 前端仍缺少 Playwright/Vitest 自动化体系。
- 前端构建仍有约 991KB 的 `request` chunk 体积警告，需要后续拆包。
- 预约叫号、中医诊疗、自动拆零 v3 和配伍禁忌仍只作为其他分支的候选能力。
- SQLite 多进程同时启动时，历史撤销流水回填尚无数据库级唯一约束；当前生产入口为单进程 Waitress，多实例部署前需补充约束或跨进程互斥。
- 登录接口尚无跨进程持久化限流；公网部署应先在 HTTPS 反向代理层限制登录请求速率。
