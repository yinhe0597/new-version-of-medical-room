# 开发日志：生产发布问题修复（2026-07-31）

## 1. 目标与结论

本轮针对上一阶段「编译 exe → SQLite→MySQL 迁移 → 本地 MySQL 测试库 → 连接启动 → 功能测试」中识别出的 5 个问题逐项处理。其中 3 项为真实代码缺陷（端口硬编码、模型漂移、会话时区），已修复；1 项为历史库兼容设计，确认无需改动；1 项为数据侧历史遗留，走既有守护式修复通道。

全量相关测试 **120 项通过**，无回归；Alembic 单 head 校验通过（head `a3f2e1c0d4b5`）。

## 2. 已完成

### 2.1 [高] 监听端口硬编码

`run_prod.py` 新增 `_resolve_server_port()`，`start_server()` 改用 `PORT = _resolve_server_port()`：

- 读取 `SERVER_PORT` 环境变量，缺省仍为 `5000`；
- 非整数或越界（1–65535 之外）时抛 `RuntimeError` 明确报错，而非静默崩溃退出；
- `.env.example` 与 `.env.production.example` 补充 `SERVER_PORT` 文档。

### 2.2 [中] `drug.monthly_sort_order` 模型漂移

该字段在 open0.0.12 引入、open0.0.14 被 `storage_location` 取代并移除功能，但迁移 `e7f8a9b0c1d2` 仍会在**新库**创建它，导致 schema 与 ORM 模型不一致。

- `backend/migrations/migration_helpers.py` 新增幂等辅助 `drop_existing_columns`（列不存在时容忍，兼容干净库）；
- 新增迁移 `a3f2e1c0d4b5_drop_drug_monthly_sort_order`（`down_revision=d8b5f0a3c2e7`），删除该列；
- 同步更新 `backend/tests/test_alembic_migrations.py`（`CURRENT_HEAD`、`allowed_legacy_columns` 清空）与 `scripts/validate_mysql_alembic.py`（head、容忍列、fresh/retry/history 各校验点）；
- 新 head = `a3f2e1c0d4b5`。

### 2.3 [低] TCM 废弃功能遗留列 —— 确认无需代码改动

核查确认没有任何迁移创建这些 TCM 列（`drug`/`visit`/`prescription_item`），全新 Alembic 建库不会出现它们。它们仅存在于被采纳的历史库（如 `ture.db`），由 `scripts/validate_mysql_alembic.py` 的 `HISTORY_EXTRA_COLUMNS` 有意容忍。与 monthly_sort_order 的本质区别：后者由迁移创建（真实漂移，需删），前者是历史数据兼容（设计如此，保留）。

### 2.4 [低] MySQL 会话时区

`backend/app/__init__.py` 的 `_configure_database` 为 MySQL/MariaDB 注册 `connect` 事件监听器，每条池连接执行 `SET time_zone = '+00:00'`：

- 用会话级设置而非 `connect_args.init_command`（后者被连接加固层明确拒绝，防止连接时注入任意 SQL）；
- 监听器注册不主动开连接，惰性触发于真实连接建立时，不影响 app factory 阶段的无连接语义；
- 残留说明：生产预检（`scripts/check_production_database.py`）使用独立连接，其 `time_zone` 提示反映的是 MySQL **服务器**默认时区，属基础设施层面，不影响应用运行时。所有时间戳均由 Python naive-UTC 计算、列为 tz-agnostic DATETIME，数据正确性与会话时区无关。
