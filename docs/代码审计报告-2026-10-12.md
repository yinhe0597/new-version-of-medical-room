> 审计日期：2026-10-12
> 审计范围：后端安全关键路径（鉴权、处方/收费/库存、备份、配置）+ 前端鉴权与打印。
> 说明：全仓 27,741 个文件，本次为**快速重点审计**，未逐行覆盖所有 `*.vue` 视图。未改动任何代码。

## 一、项目定位与技术栈

**是什么**：面向学校医务室的诊疗、处方、收费、库存与统计一体化管理系统。核心流程为「患者建档/检索 → 医生接诊开方 → 护士审核执行 → 收费与库存扣减 → 营收/库存统计」，角色有医生/护士/管理员/财务四类。

| 层级 | 技术栈 |
| --- | --- |
| 后端 | Python 3.11+、Flask（工厂模式 + Blueprint）、SQLAlchemy、Flask-JWT-Extended、Waitress、Flask-APScheduler |
| 前端 | Vue 3（Composition API）、Element Plus、Vite、Axios、Pinia、Vue Router |
| 数据库 | SQLite（默认）/ MySQL 8.0.21+，Alembic forward-only 迁移 |
| 制品 | Windows EXE（PyInstaller）、Linux tar.gz、AppImage |
| 许可证 | AGPL-3.0 |

后端核心代码约 8,600 行（`admin.py` 2705 / `nurse.py` 2352 / `doctor.py` 1393 行是三个大文件）。

## 二、总体结论

**安全基线明显高于同类项目平均水平**：SQL 全部参数化、无命令注入、密钥运行时生成、敏感数据有只读保护层、CI 有测试/静态门禁。发现的均为**加固类**问题而非可立即利用的高危漏洞——没有发现 SQL 注入、命令注入、越权、路径穿越、硬编码口令这类"硬伤"。

## 三、风险发现（按严重程度）

### 🔴 中-高

**1. 登录接口无速率限制 / 暴力破解防护缺失**
- 位置：`backend/app/api/auth.py:8-27`（`login`）
- 事实：`/api/auth/login` 无任何限流、失败锁定、指数退避或验证码。用户名不存在与密码错误统一返回 401（不泄露账号存在性，这点是对的），但可被无限次尝试。
- 影响：内网或经反代暴露后，可离线/在线爆破弱口令。系统默认引导账号 `admin/doctor/nurse` 若未及时改密，风险被放大。
- 建议方向：引入速率限制（如 Flask-Limiter，按 IP + 用户名维度），或失败次数锁定。

### 🟡 中

**2. 财务金额以浮点 `Double` 存储，存在精度风险**
- 位置：`backend/app/models/__init__.py` —— `Drug.price`(L101)、`Visit.total_amount/consultation_fee`(L154-155)、`PrescriptionItem.amount/price_at_visit/new_amount/purchase_cost`(L188-199)、`Payment.amount`(L237) 等均为 `db.Double`。
- 事实：`README.md` 与《生产上线执行清单》已自述"收费作为正式财务账时应先完成 Numeric/Decimal 迁移评估"。`revenue.py` 已用 `Decimal` 做分摊对账，说明团队已知此问题。
- 影响：浮点累计可能在 0.01 元级别出现账实不符；正式财务对账场景不满足精确性要求。
- 建议方向：存储/计算统一迁 `Numeric(10,2)`（或 Decimal），这是 README 已列出的待办项。

### 🟢 低

**3. JWT 有效期 7 天偏长**
- 位置：`backend/config.py:426`（`JWT_ACCESS_TOKEN_EXPIRES = timedelta(days=7)`）
- 缓解：`token_version` 撤销机制已实现（`app/__init__.py:483-497`），改密/禁用即令旧令牌失效。但令牌泄露后的窗口期仍为最长 7 天。
- 建议方向：评估缩短至数小时，或引入 refresh token。

**4. 诊查费 `consultation_fee` 由医生客户端传入，仅校验非负/有限，无上限**
- 位置：`backend/app/api/doctor.py:601-606`（`_parse_nonnegative_money` 校验）
- 事实：药品单价由服务端 `drug.price` 派生（无客户端改价），但诊查费是医生可自由填写的数值，只有"非负、有限"约束。
- 判断：属业务信任边界（有操作日志留痕），非漏洞；但建议加合理性上限或按挂号类型固定。

### ℹ️ 提示（非漏洞，记录确认结论）

**5. 前端路由守卫是纯客户端（role 存 localStorage）**
- `frontend/src/router/index.js:222-238`、`frontend/src/store/user.js`。客户端 role 可被篡改，但**真实边界在后端**：所有写接口均有 `@role_required(...)`（已逐一核对 `admin/nurse/doctor/finance` 的 route 装饰器）。前端守卫仅为 UX，非安全边界。结论：设计正确。

**6. 打印用 `document.write(innerHTML)`**
- `frontend/src/views/nurse/ExecutePrescription.vue:581`、`HistoryList.vue:364`、`doctor/PrescriptionHistory.vue:398`。当前全仓**无 `v-html`**，Vue 文本插值已转义，故低风险。仅提示：未来若引入 `v-html` 渲染病历/诊断文本，此处拼接会成为 XSS 面。

## 四、做得好的地方（已验证）

- **无 SQL 注入**：全 ORM 参数化查询；`text()` 均为静态 SQL，无用户输入拼接。
- **无命令注入**：mysqldump 以**列表**传参（非 shell），密码经 `MYSQL_PWD` 环境变量传递（`admin.py:154-216, 289-359`）；`--single-transaction` 保证一致性快照。
- **CSV 公式注入防护**：导入时对 `= + - @` 开头的单元格加 `'` 前缀（`admin.py:547-550`）。
- **密钥管理**：运行时生成随机密钥 + placeholder 检测（`runtime_secrets.py`），跨平台文件锁（Windows mutex / `fcntl.flock`），原子写 + `fsync`。
- **令牌撤销**：`token_version` 机制，改密/禁用/角色变更即失效。
- **权限**：角色白名单，管理员接口**不可创建 admin**（`admin.py:2547`）；密码策略 12+ 字符。
- **库存一致性**：进程内 `RLock` + MySQL `GET_LOCK` 串行化（`stock_lock.py`），行级 `with_for_update`；收费扣库存 + 生成 Payment + 写流水在同一事务内，异常整体回滚（`nurse.py:1693-1942`）。
- **状态机**：`VISIT_ALLOWED_STATUS_TRANSITIONS` 强制合法流转，拒绝非法跳转（`models/__init__.py:23-29`）。
- **MySQL 生产安全**：远程强制 verified TLS、fail-closed 运行时配置校验、连接参数白名单（`config.py` / `app/__init__.py`）。
- **CI 门禁**：前端 Vitest、后端 unittest、ruff、Alembic 单 head 门禁。
- **数据资产保护**：`data/ture.db` 等只读属性 + `gitignore` 排除 `data/`、`.env`、`*.db`；已确认 git 无敏感文件被跟踪。
