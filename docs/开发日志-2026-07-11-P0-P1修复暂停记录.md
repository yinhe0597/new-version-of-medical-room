## 3. Alembic 迁移链：已定位，修复未完成

### 3.1 已确认的阻断问题

1. 普通应用工厂会先执行运行时 schema 同步，空库执行 Alembic 时会先出现现行表，随后历史 migration 因表已存在失败。
2. 即使隔离运行时 schema 同步，历史 revision `03af525657e5` 的 `upgrade()` 仍会删除 `drug`、`user`、`patient`、`payment`、`visit`、`prescription_item` 等核心表。
3. 迁移链随后在 `4f7a1c2b3d4e` 操作 `visit` 表时触发 `NoSuchTableError`。
4. 因此当前仓库的“空库 `upgrade head`”不可用，旧 revision 还存在潜在数据破坏风险。

### 3.2 暂停时工作区中的 WIP

- `create_app(..., initialize_database=False)` 和 `create_migration_app()`：迁移时跳过运行时建表、数据修复和调度器。
- `backend/migration_app.py`：提供专用 Flask-Migrate 入口。
- `03af525657e5`：正在改为只新增/删除其职责内字段，不再删除核心表。
- `b6e1d8f3a2c4_current_model_schema_baseline.py`：桥接历史 head 与当前 ORM schema。
- `test_alembic_migrations.py`：覆盖空 SQLite 升级、模型结构对齐和历史数据保留。
- `backend/migrations/env.py`：调整 Flask-SQLAlchemy 3 的 engine 获取顺序。

这些文件在暂停前尚未完成最终测试和代码复审。恢复开发后必须先运行迁移定向测试，不能直接发布或对生产库执行。
