## 一、严重缺陷修复：医生端搜索学生信息失败

### 问题现象

系统编译部署到其他机器后，医生搜索学生时始终无结果返回。

### 根因分析

`backend/app/api/doctor.py` 的 `search_patient()` 函数中，数据库连接被硬编码为开发机器上的绝对路径：

```python
# 问题代码（已删除）
db_path = os.path.abspath("E:\\yws2\\medical-room-management-system\\ceshi\\app.db")
conn = sqlite3.connect(db_path)
```

该函数绕过了 Flask-SQLAlchemy 的数据库连接管理，直接使用 `sqlite3.connect()` 连接了一个写死的路径。部署到其他机器后，该路径不存在，导致永远查不到数据。

### 修复方案

删除整段硬编码的 `sqlite3` 直连代码，改为使用 SQLAlchemy ORM 查询，与项目其他 API 保持一致：

```python
like_kw = f"%{keyword}%"
like_lower = f"%{kw_lower}%"

patients = Patient.query.filter(
    or_(
        Patient.name.ilike(like_kw),
        Patient.student_id.ilike(like_kw),
        Patient.phone.ilike(like_kw),
        Patient.name_pinyin.ilike(like_lower),
        Patient.name_initials.ilike(like_lower),
    )
).limit(50).all()
```

**修复效果：** 无论部署到任何机器、任何路径，搜索功能都会自动使用 Flask 配置中的正确数据库，不再依赖写死的路径。

### 验证结果

使用部署包中包含 14550 个患者记录的数据库测试：
- 搜索 "1" → 50 条结果
- 搜索 "195" → 18 条结果
- 搜索 "205" → 50 条结果
- 搜索 "zhang"（拼音搜索）→ 50 条结果

## 二、SPA 路由兜底修复

### 问题现象

部署后刷新页面（如 `/doctor/history`）返回 404，前端白屏。

### 根因分析

Vue Router 使用 `createWebHistory`（HTML5 History 模式），当用户在非根路径刷新页面时，浏览器向服务器请求 `/doctor/history`，Flask 的 catch-all 路由尝试从 dist 目录寻找对应文件（不存在），返回 404。

### 修复方案

修改 `backend/app/__init__.py` 的 catch-all 路由：

```python
@app.route('/')
@app.route('/<path:path>')
def serve_frontend(path='index.html'):
    dist_dir = _get_dist_dir()
    full_path = os.path.join(dist_dir, path)
    if path != 'index.html' and not os.path.isfile(full_path):
        # 文件不存在，回退到 index.html 让 Vue Router 处理
        path = 'index.html'
    return send_from_directory(dist_dir, path)
```

逻辑：真实文件（JS/CSS/图片）直接返回，非文件路径一律回退到 `index.html`，由前端 Vue Router 接管路由。

## 五、经验总结

1. **永远不要在 API 代码中硬编码数据库路径** — 应统一通过 Flask-SQLAlchemy 的连接管理，由配置文件/环境变量控制
2. **SPA 应用由后端服务静态文件时，必须实现 history fallback** — 所有非文件请求回退到 `index.html`
3. **部署前检查清单**：搜索代码中是否残留开发环境的绝对路径（`grep -r "E:\\" backend/`）
