# 开发日志 v26.05.06.12.36（2026-05-06）

## 本次更新概述

修复药品价格浮点精度问题，解决散装药品"显示价格与计算金额不一致"的缺陷。

---

## 一、问题现象

医生开处方时，山莨菪碱片(654-2)(散) 单价显示 ¥0.20，数量 12，但小计显示 ¥2.36 而非预期的 ¥2.40。

## 二、根因分析

散装药品单价通过"整装价 / 包装数量"计算得出，例如：

```
14.76 ÷ 100 × 加价率 = 0.19680000000000003
```

这是 IEEE 754 浮点数精度的固有问题（十进制小数无法被二进制精确表示）。该值被**原样存入数据库**，未做四舍五入。

前端显示用 `.toFixed(2)` 将 0.1968 显示为 ¥0.20，但计算小计时用的是真实值：

- 显示：12 × ¥0.20 = 应为 ¥2.40
- 实际：12 × ¥0.1968... = ¥2.36

**影响范围**：数据库中 125 个散装药品中有 81 个（65%）存在此问题。

## 三、修复方案

核心原则：**显示值 = 计算值 = 存储值**，全链路统一精度到分（两位小数）。

### 1. 数据库层

对所有药品的 `price` 和 `purchase_price` 执行 `round(price, 2)`，共修复 135 条记录。

### 2. 后端层（doctor.py）

创建处方时，单价和小计在参与计算前先 round：

```python
# 修复前
unit_price = drug.price or 0.0
item_amount = quantity * unit_price

# 修复后
unit_price = round(drug.price or 0.0, 2)
item_amount = round(quantity * unit_price, 2)
```

同样处理了 `purchase_cost`（采购成本）的计算。

### 3. 前端层（VisitForm.vue / DirectPurchase.vue）

药品加入处方列表时 price 先 round：

```javascript
// 修复前
price: drug.display_price,

// 修复后
price: Math.round(drug.display_price * 100) / 100,
```

小计计算和总金额累加统一用 round：

```javascript
// 修复前
sum + (item.price * item.quantity)

// 修复后
sum + Math.round(item.price * item.quantity * 100) / 100
```

## 四、涉及文件

| 文件 | 改动说明 |
|------|---------|
| `backend/app/api/doctor.py` | `unit_price`、`item_amount`、`purchase_cost` 统一 `round(..., 2)` |
| `frontend/src/views/doctor/VisitForm.vue` | price 赋值、小计计算、总金额计算统一 round |
| `frontend/src/views/doctor/DirectPurchase.vue` | 同 VisitForm 修复 |
| 数据库（3 份） | 修复 135 条浮点精度异常的药品价格记录 |
