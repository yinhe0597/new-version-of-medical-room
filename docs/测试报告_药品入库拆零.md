# 测试报告：药品入库（整包装/拆零）与联动库存

## 1. 单元测试（后端 Java 模块）

位置：`backend-java/src/test/java/com/medical/stock/service/DrugStockServiceTest.java`

- 正则校验：整份规格 `20 mg×100粒/瓶` 可通过；非法格式会抛出异常
- 单价阈值：`threshold = packPrice * minSaleAmount / packAmount`，示例 `10.00 * 2 / 100 = 0.200000`
- 数量换算：入库 3 瓶、包装量 100 粒、最小销售 2 粒 → 拆零数量 150
- 批次唯一性：基于 `name/specification/batchNo` 归一化构造唯一键，大小写与空白不影响

## 2. 集成测试（Flask 后端 + 数据库）

建议用例：

- 连续录入 10 条不同规格药品
  - 未勾选可零售：应新增 10 条整包装记录
  - 勾选可零售：应新增 10 条整包装 + 10 条拆零记录，并在 `drug_stock_group` 中新增 10 条 group

验证点：

- 相同 药品名称 + 规格 + 批次号：后端返回 409，前端弹窗提示重复
- 扣减库存：医生端选择整装/零散任一行开方后，护士执行结算时联动扣减并同步两行库存数量

## 3. 性能测试（联想下拉 1000 条）

策略：

- 前端联想使用远程检索（最多 20 条）+ 180ms debounce，避免一次性渲染 1000 条
- 后端按 `Drug.name`/`Drug.base_name` 索引做 contains 检索并 limit

评估方式（浏览器端）：

- 打开护士端入库页，输入关键字触发联想
- 以 `performance.now()` 统计“键入 → 选项列表渲染完成”的耗时，要求 < 200ms（受网络与机器影响需在同一环境重复取样）
