## 1. 项目是什么

一套面向 **高校/中小学医务室** 的全栈诊疗管理系统，覆盖：

```
挂号/建档 → 医生接诊开方 → 护士审核 → 改价收费 → 库存扣减 → 营收统计
```

### 角色体系

| 角色 | 职责 | 前端路径 | API 前缀 |
|------|------|---------|---------|
| **doctor** | 患者检索/建档、接诊开方、病历查询 | `/doctor/` | `/api/doctor/` |
| **nurse** | 处方审核/执行、库存管理、收费结算 | `/nurse/` | `/api/nurse/` |
| **admin** | 药品字典、用户管理、统计报表 | `/admin/` | `/api/admin/` |
| **finance** | 财务看板、营收统计（只读） | `/finance/` | (复用 admin API) |

### 四端（四个独立前端界面）

| 界面 | 侧边栏菜单 |
|------|-----------|
| **医生端** | 患者搜索、现病史模板、体格检查模板、医生贴士模板、零散用药、历史处方 |
| **护士端** | 待处置处方、历史诊疗记录、库存管理、药品管理、出库报表、统计数据 |
| **管理端** | 账号管理、药品管理、人员档案、营收统计、药品出库报表、财务看板、运营日志、系统设置 |
| **财务端** | 财务看板、营收统计、药品出库报表、药品价格查看（只读） |

## 5. 核心业务逻辑详解

### 5.1 处方状态机

```
                    ┌──────────┐
                    │  pending  │  ← 医生开方完成
                    └────┬─────┘
                         │
              ┌──────────┼──────────┐
              │          │          │
              ▼          ▼          ▼
        ┌──────────┐ ┌──────────┐
        │rejected  │ │nurse_    │  ← 护士审核通过
        │          │ │verified  │
        └──────────┘ └────┬─────┘
              │            │
              │            ├── 护士改价/追加项目
              │            │
              │            ▼
              │      ┌──────────┐
              │      │completed │  ← 护士执行（扣库存+结算）
              │      └────┬─────┘
              │            │
              │            ▼
              │      ┌──────────┐
              │      │ revoked  │  ← 护士撤销
              │      └──────────┘
              │
              └── 医生修改病历后重新变为 pending
```

**状态转移规则**（定义在 `models/__init__.py` 的 `VISIT_ALLOWED_STATUS_TRANSITIONS`）：

| 当前状态 | 允许的下一个状态 |
|----------|----------------|
| pending | nurse_verified, rejected |
| nurse_verified | completed, rejected |
| completed | revoked |
| rejected | (终端) |
| revoked | (终端) |

### 5.2 核心业务流程

```
患者来诊
   │
   ├── 已建档 → 医生搜索患者 → 选择就诊
   │                    │
   └── 未建档 → 医生创建患者档案
                       │
                       ▼
                医生开立就诊（病历+处方）
                  ├── ICD-10 诊断选择
                  ├── 药品选择（支持拼音搜索）
                  ├── 整装/散装选择
                  ├── 静脉给药配伍组
                  └── 库存校验（药品 type=1）
                       │
                       ▼
                 护士待处理列表
                       │
              ┌────────┼────────┐
              │        │        │
              ▼        ▼        ▼
            驳回   改价(可选)  审核通过
              │    追加项目     │
              │     (可选)      │
              │                ▼
              │           执行处方
              │        ├── 扣减库存
              │        ├── 生成 Payment
              │        └── status=completed
              │
              └── 医生修改后重新提交
```

### 5.3 库存管理机制

药品有三种类型：

| type | 含义 | 库存行为 |
|------|------|---------|
| 1 | 药品 | 参与库存校验和扣减 |
| 2 | 诊疗项目 | 不占用库存（stock=-1） |
| 3 | 耗材 | 参与库存校验和扣减 |

**整散装模式**：
- 整装：按盒/瓶售卖，`price` 为整装价
- 散装：按最小单位售卖，`has_scattered=true`，`scattered_price` + `conversion_rate`
- 扣库存：`stock_deduct = ceil(quantity / conversion_rate)`

**库存组模式**（`DrugStockGroup`）：
- 整装 + 散装共享 `total_units`
- 出库时同步调整整装和散装的账面库存

### 5.4 认证与鉴权链路

```
1. 登录 → POST /api/auth/login → 返回 JWT access_token
2. 前端 → localStorage 存储 token + user
3. 每次请求 → Axios 拦截器注入 Authorization: Bearer <token>
4. 后端 → @role_required('doctor') 装饰器校验角色
5. 前端 → router.beforeEach 根据 meta.role 限制页面访问
6. Token 过期 → 默认 7 天（config.py 配置）
```

## 6. 常见二次开发任务

### 6.1 新增数据库字段

1. 在 `backend/app/models/__init__.py` 中给对应模型加字段
2. 确认 `backend/app/__init__.py` 的 `_sync_model_schema()` 能同步该可空字段，并为正式环境编写、审查 Alembic migration
3. 生成迁移脚本：`flask db migrate -m "描述"`
4. 应用迁移：`flask db upgrade`
5. 前端对应组件中补充字段展示/编辑

### 6.2 新增后端 API

1. 在 `backend/app/api/` 下对应角色文件添加路由
2. 使用 `@role_required('role_name')` 控制权限
3. 继承 `bp`（蓝图）做路由注册
4. 返回 JSON，异常时 `db.session.rollback()`
5. （推荐）在 `backend/tests/` 添加测试用例

### 6.3 新增前端页面

1. 在 `frontend/src/views/` 对应角色目录下创建 `.vue` 组件
2. 在 `frontend/src/router/index.js` 添加路由 + `meta.role`
3. 在对应角色的 `Dashboard.vue` 侧边栏菜单中添加入口
4. 使用 `import request from '@/api/request'` 调用后端接口

### 6.4 新增角色

1. **后端**：在 User.role 支持新角色（如 `pharmacist`）
2. **后端**：在 `decorators.py` 中 `role_required` 已通用支持多角色
3. **前端**：新建 `frontend/src/views/pharmacist/` 目录
4. **前端**：在 `router/index.js` 添加新角色的路由组
5. **前端**：在 `Login.vue` 中确保路由跳转兼容

### 6.5 修改业务流程

> ⚠️ **重要**：涉及金额计算、库存扣减、状态流转的逻辑，务必同时修改：
> - 后端校验（业务规则的第一道防线）
> - 前端校验（用户体验）
> - 测试用例（`backend/tests/`）
> - 文档（`docs/` 下对应说明）

## 7. 数据库与模型

### 7.1 核心模型关系

```
User ──┐                    Drug ──┐
       │                           │
       ├──< Visit (doctor)         ├──< PrescriptionItem
       │       │                   │
       │       ├──< Patient        ├──< InventoryRecord
       │       │                   │
       │       ├──< PrescriptionItem ──< DrugStockGroup
       │       │                   │
       │       └──< Payment        └──< DailyStockSnapshot
       │
       └──< Payment (nurse)

DiagnosisDict    TextTemplate    OperationLog
```

### 7.2 核心模型字段速查

**Visit（就诊记录）** — 核心表
- `patient_id` → Patient
- `doctor_id` → User
- `status`: pending / nurse_verified / rejected / completed / revoked
- `consultation_fee`, `total_amount`
- `diagnosis`, `chief_complaint`, `present_illness`, `past_history`, `physical_exam`, `doctor_advice`

**PrescriptionItem（处方明细）**
- `visit_id` → Visit, `drug_id` → Drug
- `usage`, `dosage`, `frequency`, `timing`, `days`, `quantity`
- `price_at_visit`, `amount`, `purchase_cost`
- 改价审计：`original_price`, `original_amount`, `new_price`, `new_amount`, `modified_by`, `modified_at`
- 静脉给药：`is_intravenous`, `infusion_group`, `infusion_dosage_value`, `infusion_dosage_unit`, `infusion_method`

**Drug（药品字典+库存）**
- `type`: 1=药品, 2=诊疗项目, 3=耗材
- `price`, `purchase_price`, `stock`, `status`
- `has_scattered`, `scattered_price`, `conversion_rate`
- `batch_no`, `inbound_at`, `variant_type`, `stock_group_code`

**Payment（支付）**
- `visit_id` (唯一), `nurse_id`, `amount`, `payment_method`
- `is_employee_discount`, `receipt_printed`

### 7.3 数据库迁移

```bash
cd backend
source .venv/Scripts/activate
flask db migrate -m "添加了某某字段"
flask db upgrade
```

> 注意：应用启动时的 `_sync_model_schema()` 只负责幂等创建缺失表、可空字段和索引，不处理删列、改类型、非空约束或数据回填；这些变更必须使用 Alembic migration。

## 8. 版本与发布规范

### 主干不污染原则（参考 `docs/主开发记录.md`）

- **主干（main/master）只接收经过验证的合并**
- 每个需求/版本使用独立分支开发（如 `feature/v1.06-*`）
- 构建产物统一放入约定目录，通过 `.gitignore` 忽略
- 每个可交付版本用 tag 固化
- 每次打包必须落一条"编译记录"

### 建议的工作流

```bash
# 1. 从主干创建功能分支
git checkout -b feature/my-new-feature

# 2. 开发 + 测试
# ... 修改代码 ...
python -m unittest discover -s tests -p 'test_*.py'

# 3. 合并回主干
git checkout main
git merge feature/my-new-feature
git tag v0.1.0
```
