# 项目介绍（Medical Room Management System）

## 1. 这是一个什么项目

这是一个面向学校医务室的“诊疗业务 + 处方流转 + 库存/进销存 + 收费结算 + 统计报表”的信息化系统，用于把纸质流程在线化，形成可追溯、可统计、可协作的工作闭环。

系统按角色拆分职责与界面：

- 医生：面向诊疗与开方
- 护士：面向处方审核/执行与库存扣减、收费结算
- 管理员：面向药品字典/库存维护、导入、统计与系统维护

## 2. 技术栈与总体架构

总体形态：前后端分离 B/S 架构。

- 前端：Vue 3 + Vite + Pinia + Element Plus（目录：`frontend/`）
- 后端：Flask + Flask-SQLAlchemy + Flask-Migrate + Flask-JWT-Extended（目录：`backend/`）
- API 前缀：`/api`
- 认证方式：登录获取 JWT，前端请求携带 `Authorization: Bearer <token>`
- 数据库连接：优先读取 `DATABASE_URL`/`SQLALCHEMY_DATABASE_URI` 环境变量，未设置时默认使用 SQLite（`data/app.db`）

## 3. 目录结构与模块边界（快速定位）

### 3.1 后端（Flask）

- `backend/run.py`：开发启动入口
- `backend/app/__init__.py`：应用工厂（create_app）与蓝图注册
- `backend/app/api/`：按角色拆分的 API（`auth.py`、`admin.py`、`doctor.py`、`nurse.py`）
- `backend/app/models/__init__.py`：核心数据模型与业务字段
- `backend/app/utils/decorators.py`：鉴权装饰器（按角色校验）

### 3.2 前端（Vue）

- `frontend/src/main.js`：应用入口
- `frontend/src/router/index.js`：路由定义与角色守卫（按 doctor/nurse/admin）
- `frontend/src/store/user.js`：用户与 token 状态
- `frontend/src/api/request.js`：Axios 封装、token 注入与错误处理
- `frontend/src/views/`：按角色拆分页面（`admin/`、`doctor/`、`nurse/`）与登录页

## 4. 鉴权与权限（从登录到访问控制）

### 4.1 登录与 token

- 后端登录接口：`POST /api/auth/login`
- 成功返回 `access_token`（JWT）
- 前端把 token 写入本地存储，并在请求拦截器中自动加 Bearer Token

### 4.2 角色权限

- 前端：路由 `meta.role` 做页面访问限制
- 后端：用装饰器对接口做角色校验（例如管理员接口仅 admin 可用）

## 5. 关键业务闭环（从患者到结算）

### 5.1 患者检索/建档（医生）

- 通过学号/姓名检索患者
- 未命中可新建患者档案

### 5.2 接诊开方（医生）

- 录入就诊信息、诊断与医嘱
- 录入处方明细：用法用量、频次、服用时间、天数、数量等
- 支持 ICD-10 诊断检索辅助录入
- 形成“就诊（Visit）+ 处方明细（PrescriptionItem）”的组合记录

### 5.3 护士审核/执行/扣减库存与结算（护士）

- 护士端获取待处理列表，查看处方详情
- 执行处方时做二次校验，并扣减库存（包含散装折算逻辑）
- 生成支付记录（Payment）并更新就诊状态

### 5.4 统计与维护（管理员）

- 药品字典与库存维护（启停用、批量导入、合并重复等）
- 营收/成本/利润统计与明细
- 系统维护（例如数据库备份）

## 6. 功能清单（按角色）

### 6.1 医生（doctor）

- 患者检索与建档
- 接诊开方（含诊断/医嘱/处方明细录入、金额计算、库存校验）
- 历史处方/就诊记录查询（支持日期筛选）

### 6.2 护士（nurse）

- 待处理处方列表
- 处方审核/改价/驳回/执行
- 执行时库存扣减与收费结算、票据状态
- 库存查看、盘点与调整流水

### 6.3 管理员（admin）

- 用户管理（医生/护士账号维护、密码重置等）
- 药品/项目字典维护与库存维护（批量导入、合并重复、低库存预警）
- 统计报表（营收/成本/利润）
- 系统维护（例如数据库备份）

## 7. 关键入口点（建议从这里开始二次开发）

### 7.1 前端入口

- 路由：`frontend/src/router/index.js`
- 请求层：`frontend/src/api/request.js`
- 页面：`frontend/src/views/`（按角色拆分）

### 7.2 后端入口

- 启动：`backend/run.py`
- 应用工厂：`backend/app/__init__.py`
- API：`backend/app/api/*.py`
- 数据模型：`backend/app/models/__init__.py`
