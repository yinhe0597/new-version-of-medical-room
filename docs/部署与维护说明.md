# 校医务室诊疗管理系统 V1.08 部署与维护说明

更新时间：2026-03-27

## 1. 系统简介

- 架构：前后端分离（Vue 3 + Flask）
- 数据库：SQLite（打包默认）或通过 `DATABASE_URL` 配置 MySQL
- 端口：
  - 前端：5888
  - 后端：5000
  - 数据库：3306（仅使用 MySQL 时）

## 2. 数据库部署选择

默认 SQLite 无需安装独立数据库服务，程序使用项目根目录的 `data/app.db`。仅在明确选择 MySQL 时执行以下操作：

1. **创建医务室专用账号**
   - 使用部署环境自己的高强度密码，不在代码或文档中保存共享密码。
   - 建议仅允许应用服务器地址连接，并只授予 `medical_db` 所需权限。
   - 通过 `.env` 中的 `DATABASE_URL` 配置，示例见根目录 `.env.example`。

2. **运行数据库建库脚本**
   在 MySQL 中运行根目录 `init_database.sql` 创建 `medical_db`；账号和授权语句需由部署人员使用实际强密码单独执行。

   完成后在 `.env` 中设置 `DATABASE_URL`，并在真实 MySQL 环境完成迁移和备份恢复验收。

## 3. 开发环境快速启动（Windows）

- 一键启动：运行项目根目录的 `start_dev.bat`
- 手动启动
  - 后端：进入 `backend/`，安装依赖后运行 `python run.py`
  - 前端：进入 `frontend/`，安装依赖后运行 `npm run dev`

## 4. 生产部署建议（Windows Server）

- 后端：推荐使用 `waitress` 部署 Flask，默认仅监听 `127.0.0.1`；不得直接暴露调试服务器
- 前端：构建生成 `frontend/dist/` 后由 Nginx/IIS 通过 HTTPS 托管，并代理 `/api` 到后端
- 局域网部署：仅在反向代理或防火墙已就绪时设置 `SERVER_HOST=0.0.0.0`
- 密钥：必须配置至少 32 位的 `SECRET_KEY`、`JWT_SECRET_KEY`，多进程实例必须完全一致
- 数据备份：定期在后台使用“一键备份数据”；SQLite 下载 `.db`，MySQL 下载 `.sql`，也可使用数据库侧定时备份

## 5. 常见维护事项

- 首次账号密码使用 `BOOTSTRAP_PASSWORD` 或控制台随机临时密码，上线后立即修改
- 历史版本曾提交过 MySQL 示例凭据；已部署环境必须轮换或删除旧账号，并限制账号来源地址
- 升级前先备份数据库，再替换程序文件
- 如遇异常日志或启动失败，优先检查端口占用与依赖完整性
