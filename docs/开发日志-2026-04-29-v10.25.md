## 新增功能

### 1. 医生端"快速接诊"模式

#### 需求背景
校医务室排队高峰期，医生需要填写大量病历字段（主诉、现病史、既往史、体格检查等）才能提交处方，影响接诊效率。

#### 实现方案
- 在接诊界面"电子病历"卡片头部增加"快速接诊"复选框
- 勾选后隐藏 5 个非必填字段（主诉、现病史、既往史、体格检查、医生留言），仅保留"诊断"字段
- 使用 `v-show` 而非 `v-if`，切换时不丢失已填内容
- 确认提交弹窗中同步适配，quickMode 时显示提示"快速接诊模式，其余病历信息可稍后补充"
- 提交逻辑无需修改，后端本身允许这些字段为空

#### 修改文件
- `frontend/src/views/doctor/VisitForm.vue`

### 2. 历史就诊记录"补充病历"功能

#### 需求背景
快速接诊后提交的处方缺少病历详情，医生需要在空闲时补充完善。

#### 实现方案

**后端新增 API：**
- `PUT /api/doctor/visits/<id>/medical-record`：补充病历接口
  - 权限：仅本人处方可操作
  - 状态限制：rejected 状态不允许（有"重新开方"功能），其余状态均允许
  - 允许更新字段：chief_complaint、present_illness、past_history、physical_exam、doctor_advice
  - 空值保护：只更新请求中 strip() 后非空的字段，不覆盖已有内容

**后端修改 API：**
- `GET /api/doctor/visits/history`：返回数据新增 `medical_record_incomplete` 布尔字段
  - 判断逻辑：chief_complaint、present_illness、physical_exam 三个核心字段全为空时为 true

**前端改动：**
- 历史就诊记录页面新增"补充病历"按钮（绿色，条件显示：incomplete 且非 rejected）
- 新增补充病历弹窗，包含 5 个 textarea 表单字段
- 交互流程：点击按钮 -> 获取详情回显已有内容 -> 医生填写 -> PUT 提交 -> 刷新列表 -> 按钮自动消失

#### 修改文件
- `backend/app/api/doctor.py`
- `frontend/src/views/doctor/PrescriptionHistory.vue`

## 问题修复

### 3. 数据库 Schema 兼容性问题

#### 问题描述
切换到 feature/refined-revenue-report 分支后，新版代码模型包含旧数据库中不存在的列（visit 表的 verified_by、verified_at、rejected_by 等），导致 API 查询报错 `no such column: visit.verified_by`。

#### 解决方案
在 `backend/app/__init__.py` 的 `create_app()` 中利用已有的 `_ensure_sqlite_column()` 机制，自动为 visit、prescription_item、drug 三张表补充缺失列：

- visit 表：verified_by, verified_at, rejected_by, rejected_at, reject_reason
- prescription_item 表：original_price, original_amount, new_price, new_amount, modified_by, modified_at, modify_reason
- drug 表：variant_type, stock_group_code, unit_amount, base_name

#### 修改文件
- `backend/app/__init__.py`

### 4. 药品散装标记容错处理

#### 问题描述
数据库中"阿莫西林胶囊(散)"等散装药品的 `has_scattered` 字段为 0、相关联动字段为 NULL，但前端可能将其标记为 `is_scattered=true`，导致后端报错 "Drug xxx does not support scattered sale"。

#### 问题根因
旧版数据库的药品数据未适配新版"整散装联动"模型，散装药品作为独立品种存在（名称带"(散)"后缀），不需要走联动逻辑。

#### 解决方案
将后端 `create_visit()` 中的硬拒绝逻辑改为自动降级：
```python
# 修改前：报错拒绝
if is_scattered and not drug.has_scattered:
    return jsonify({"msg": f"Drug {drug.name} does not support scattered sale"}), 400

# 修改后：自动降级为普通售卖
if is_scattered and not drug.has_scattered:
    is_scattered = False
```

#### 修改文件
- `backend/app/api/doctor.py`
