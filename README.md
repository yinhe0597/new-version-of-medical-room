## ✨ 项目简介

本项目是一套面向高校/中小学医务室场景的**全栈诊疗与药品/耗材管理系统**，覆盖"接诊开方 → 护士审核 → 发药结算 → 库存与营收统计"的完整业务闭环。

系统采用 **医生 / 护士 / 管理员 / 财务** 四角色独立界面设计，各角色权限边界清晰，操作流程贴合真实校医务室工作场景。无论是日常接诊高峰期的快速开方，还是月末库存盘点与营收报表，都能高效完成。

### 🌟 核心优势

- 🔄 **全流程闭环**：从患者挂号到处方结算，每一步都有系统支撑
- 🎒 **三类物资管理**：药品 + 诊疗项目 + 耗材，统一管理但各行其道
- 🔒 **安全兜底**：处方提交与审核均有后端强校验，杜绝绕过业务规则
- 💊 **库存实用**：支持"整包装 + 拆零"联动入库与扣减，适配真实发药场景
- 🏗️ **角色清晰**：Admin / Doctor / Nurse / Finance 按职责拆分能力与接口
- 🚀 **易部署**：SQLite 零配置启动，PyInstaller 打包开箱即用
- 🔄 **受控升级**：安全增量补齐可空字段和索引，复杂结构升级使用正式 migration
- 📊 **数据洞察**：营收统计（药品/诊疗/耗材三路拆分）、药品消耗、医生工作量多维报表
- 🔐 **账号可追溯**：账号停用保留历史业务归属，改密、重置和停用立即注销旧 JWT
- 🧾 **库存可核对**：执行与撤销写入结构化流水，跨日月报按北京时间保持库存守恒

## 🚀 快速开始

### 方式一：Windows 直接运行（推荐）

```
1. 下载最新 Release 包
2. 双击 医务室管理系统.exe
3. 浏览器访问 http://localhost:5000
```

### 方式二：Linux 部署

提供两种打包格式，适用于不同场景：

**格式 A：tar.gz 压缩包（服务器 / 远程机器）**
```bash
# 解压
tar xzf 医务室管理系统-v0.0.16-linux.tar.gz
cd 医务室管理系统-v0.0.16-linux

# 后台启动（自带进程管理）
./run.sh start

# 其他命令
./run.sh stop      # 停止
./run.sh restart   # 重启
./run.sh status    # 查看状态
./run.sh log       # 查看实时日志
```

**格式 B：AppImage 单文件（桌面 Linux / U盘携带）**
```bash
chmod +x 医务室管理系统-v0.0.16-linux.AppImage
./医务室管理系统-v0.0.16-linux.AppImage
```

> 💡 Linux 版启动后自动在程序同级目录创建 `data/` 和 `logs/`，无需手动配置数据库。

**从源码构建 Linux 包：**
```bash
# 需要 Python 3.8+ 和 Node.js 22.12+
bash build_linux.sh
# 输出到 dist_linux/ 目录，包含 tar.gz 和 AppImage 两种格式
```

### 方式三：源码开发

**后端 (Python 3.8+)**
```bash
cd backend
python -m venv .venv
# 激活虚拟环境 (Windows: .venv\Scripts\activate | Linux/Mac: source .venv/bin/activate)
pip install -r requirements.txt

# 初始化数据库结构与基础账号
python init_db.py

# (可选) 导入 ICD-10 疾病字典数据
python import_icd10.py

# 启动开发服务器
python run.py
```

**前端 (Node.js 22.12+)**
```bash
cd frontend
npm install
npm run dev
```

**后端测试（项目根目录）**
```bash
python run_backend_tests.py
```

### 🔑 首次账号

系统按需创建 `admin`、`doctor`、`nurse` 三个基础账号。密码使用 `BOOTSTRAP_PASSWORD`
或启动控制台打印的随机临时密码，不再提供公开固定密码；旧库中仍为 `123456` 的基础账号
会在升级启动时自动旋转。首次登录后应立即逐个修改密码。

> 开发和打包默认统一使用 `data/app.db`，外部数据库与密钥配置见 `.env.example`。

未显式设置 `SECRET_KEY`、`JWT_SECRET_KEY` 时，系统会在
`data/.runtime-secrets.json` 生成并稳定复用随机密钥。该文件属于敏感运行数据，禁止提交
Git；删除它会使现有登录令牌失效。管理员删除账号采用软停用，历史业务记录不会失去人员归属。

## 📝 V2.0.0 关键用法速记（医生端）

- **模板快捷填入**：在接诊页"主诉/体格检查/医生贴士"输入框末尾输入 `##`，弹出模板列表，点选即可插入。
- **重新开方**：在"历史就诊记录"中，状态为"已驳回"或"已撤销"的记录，操作列点击"重新开方"，会载入原处方草稿供修改并重新提交给护士审核。
- **修改病历模板快捷调用**：在"修改病历"弹窗的现病史输入框中输入 `##`，弹出模板列表，点击即可插入模板内容。
