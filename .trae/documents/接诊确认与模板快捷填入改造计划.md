# 接诊确认与模板快捷填入改造计划

## Summary
实现 4 项改造：
1. 在“保存并接诊/开始接诊”进入接诊页前，弹窗二次确认患者基本信息，确认后才跳转到接诊页。
2. 医生端左侧“患者接诊”下增加模板入口（主诉模板、体格检查模板、医生贴士模板），模板保存到后端数据库；在正式接诊表单内通过输入触发关键字弹出模板选择并快速填入。
3. 接诊页默认诊查费从 5 元改为 8 元（页面字段当前显示为“诊察费”，后续代码里保持字段名 `consultation_fee` 不变）。
4. 处方“用量”下拉：把现有“散装计数单位”（片/粒/袋/包/支/瓶/贴/喷/丸/次/滴等）补全到 6；不改动 ml/g 等非计数单位。

## Proposed Changes
### A. 接诊前二次确认（前端）
**目标**
- 点击“开始接诊/保存并接诊”后：在真正 `router.push('/doctor/visit')` 前，弹窗展示患者基本信息，必须点击“确认”才进入接诊页。
- 若先触发“补充手机号”弹窗：在保存手机号或选择“暂不补充”后，同样进入二次确认弹窗，再进入接诊页。

**改动文件**
- [PatientSearch.vue](file:///e:/yws2/medical-room-management-system/frontend/src/views/doctor/PatientSearch.vue)

**实现方式**
- 引入并使用 `ElMessageBox.confirm`（文件已 import `ElMessageBox`）。
- 新增函数 `confirmStartVisit()`：
  - 生成患者信息展示内容（学号/姓名/性别/年龄/班级/电话/是否临时人员等）。
  - `await ElMessageBox.confirm(...)` 成功后才调用现有 `router.push(...)`。
- 调整调用链：
  - `handleStartVisit()` 在手机号校验/补充流程通过后，不直接 `startVisit()`，而是 `confirmStartVisit()`。
  - `submitPhone()` / `skipPhoneInput()` 在结束后同样走 `confirmStartVisit()`。

### B. 模板管理（后端）
**目标**
- 模板持久化到后端数据库，按医生账号隔离（doctor only）。
- 支持 CRUD 与搜索：
  - 列表/搜索：按 `category` + `q` 查询；
  - 新增、编辑、删除模板。

**改动文件**
- [backend/app/models/__init__.py](file:///e:/yws2/medical-room-management-system/backend/app/models/__init__.py)
  - 新增模型 `TextTemplate`（建议字段）：
    - `id`
    - `doctor_id`（FK `user.id`，nullable=False）
    - `category`（如 `chief_complaint` / `physical_exam` / `doctor_advice`）
    - `title`
    - `content`
    - `updated_at` / `created_at`
- [backend/app/api/doctor.py](file:///e:/yws2/medical-room-management-system/backend/app/api/doctor.py)
  - 新增接口（均需 `@jwt_required()` + `@role_required('doctor')`）：
    - `GET /doctor/templates`：params `category`（必填）、`q`（可选）；返回模板列表
    - `POST /doctor/templates`：body `category,title,content`
    - `PUT /doctor/templates/<id>`：body `title,content`
    - `DELETE /doctor/templates/<id>`
- [backend/app/__init__.py](file:///e:/yws2/medical-room-management-system/backend/app/__init__.py)
  - 为避免线上已有库缺少新表导致不可用：在 import models 之后，针对 SQLite 执行一次 `db.create_all()`（包裹 try/except，不影响非 SQLite 环境）。

**数据与权限约束**
- 医生只能操作自己的模板（通过 `doctor_id == get_jwt_identity()` 过滤）。
- `category` 限制在允许集合内（后端校验，非法返回 400）。
- `title/content` 去空白后不能为空（后端校验，非法返回 400）。

### D. 正式接诊页：关键字触发模板快速填入（前端）
**目标**
- 在接诊页三个 textarea（主诉/体格检查/医生留言）内，输入触发符后弹出模板选择器，选中后把模板内容插入输入框。

**触发规则（本计划的明确决策）**
- 触发符：`##`
- 触发方式：当输入框内容末尾出现 `##`（即用户在末尾连续输入两个 `#`）时，弹出模板选择对话框。
- 插入方式：选中模板后，替换掉末尾的 `##`，把模板 `content` 追加到末尾（如末尾非空则先补一个换行）。

**改动文件**
- [VisitForm.vue](file:///e:/yws2/medical-room-management-system/frontend/src/views/doctor/VisitForm.vue)

**实现方式**
- 增加一个模板选择 `el-dialog`：
  - 顶部搜索框（对当前 category 搜索）
  - 列表（点击即插入）
- 给 3 个 `el-input type="textarea"` 增加 `@input` 或 `@keyup` 监听：
  - 当检测到值以 `##` 结尾：记录当前字段 key（`chief_complaint` / `physical_exam` / `doctor_advice`），打开 dialog，并拉取模板列表。

## Assumptions & Decisions
- 模板存储：后端数据库（按医生账号隔离）。
- 模板触发：输入关键字触发弹窗；本计划选择触发符为 `##`，且只在“末尾输入##”时触发（先做稳定可控版本）。
- 菜单结构：将“患者接诊”改为子菜单，新增 3 个模板管理入口。
- 用量扩展：仅扩展计数单位到 6，不扩展 ml/g 等单位。
